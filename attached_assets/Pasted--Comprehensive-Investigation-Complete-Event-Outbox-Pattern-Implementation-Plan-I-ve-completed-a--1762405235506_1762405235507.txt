1.1 Create Outbox Table Schema
CREATE TABLE subscription_audit_outbox (
 id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
 subscription_id UUID NOT NULL,  -- FK after subscription commits
 user_id UUID NOT NULL REFERENCES users(id),
 event_type VARCHAR(100) NOT NULL,
 old_status VARCHAR(50),
 new_status VARCHAR(50),
 metadata JSONB,
 status VARCHAR(20) DEFAULT 'pending', -- pending, processing, completed, failed
 retries INT DEFAULT 0,
 next_retry_at TIMESTAMP,
 error_message TEXT,
 created_at TIMESTAMP DEFAULT NOW(),
 processed_at TIMESTAMP
);
-- Indexes for performance
CREATE INDEX idx_outbox_status_created ON subscription_audit_outbox(status, created_at);
CREATE INDEX idx_outbox_next_retry ON subscription_audit_outbox(next_retry_at) WHERE status = 'pending';
CREATE INDEX idx_outbox_subscription ON subscription_audit_outbox(subscription_id);

Tasks:
3.1 Create Outbox Processor
File: server/services/infrastructure/subscription-audit-outbox-processor.ts
Architecture:
┌─────────────────────────────────────┐
│  Outbox Processor (runs every 2s)  │
└─────────────────────────────────────┘
         │
         ├─→ Poll outbox table (batch of 10)
         │
         ├─→ For each event:
         │   ├─ Mark as 'processing'
         │   ├─ Write to subscription_events
         │   ├─ Mark as 'completed'
         │   └─ If fails → Retry logic
         │
         └─→ Failed 5 times → Dead Letter Queue
Key features:
Poll interval: 2 seconds
Batch size: 10 events per cycle
Retry strategy: Exponential backoff (1s, 2s, 4s, 8s, 16s)
Max retries: 5
DLQ for permanent failures
3.2 Create Configuration
File: server/config/outbox-processor.config.ts
